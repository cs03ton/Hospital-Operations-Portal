# มาตรฐานวันที่ HOP

## กติกา

- วันที่สำหรับผู้ใช้แสดงปี พ.ศ. ส่วน API และฐานข้อมูลใช้ ค.ศ.
- วันที่ไม่มีเวลาใช้ `YYYY-MM-DD` และไม่ผ่านการแปลง timezone
- วันเวลาของเหตุการณ์ส่ง ISO 8601 พร้อม `Z` หรือ offset; API แปลงเป็น UTC และหน้าจอแสดงเวลา `Asia/Bangkok`
- รับปี ค.ศ. 1900–2100 หรือ พ.ศ. 2443–2643 แปลงปีก่อนตรวจวันที่จริง เช่น `2567-02-29` → `2024-02-29`; ปฏิเสธ `2568-02-29`
- JSON DateOnly, DateTime, DateTimeOffset, query filters และช่องปีที่อยู่ในรายการ CalendarYearInput ใช้กฎเดียวกัน ตัวเลขอย่าง daysPerYear ไม่ถูกแปลง
- ปีของเลขเอกสาร ชื่อไฟล์ ข้อมูลนำเข้า ISO และข้อมูลวิเคราะห์สำหรับระบบยังใช้ ค.ศ. เวลาใน audit payload ดิบยังเป็นข้อมูลสำหรับระบบ

## จุดที่ปรับ

| ส่วน | การเปลี่ยนแปลง |
| --- | --- |
| ส่วนกลาง Frontend | AppDatePicker แสดง พ.ศ. โดยปริยาย; ตัวแสดงวันที่และวันเวลาใช้กฎเดียวกัน |
| ลา | จำนวนวันบนฟอร์มใช้ policy preview; วันหยุดนำเข้ารับทั้งสองปี; รายละเอียด ตัวกรอง มอบหมาย ปฏิทิน ยอดลา และรายงานใช้ตัวแปลงร่วมกัน |
| Fleet | เปลี่ยนช่อง datetime-local ของการมอบหมาย งานฉุกเฉิน นโยบาย ซ่อมบำรุง และ capability; เปิดแก้ไขด้วยเวลาไทย และส่ง UTC; ปฏิทิน/รายงานใช้วันไทย |
| ห้องประชุม | ฟอร์มใช้ตัวเลือกวันที่ร่วมกัน; การคำนวณขอบเขตเดือนและการจัดรายการลงวันใช้เวลาไทย |
| ประกาศ | วันเวลาเผยแพร่/หมดอายุและค่าเดิมที่เปิดแก้ไขใช้เวลาไทย |
| พนักงาน/แจ้งซ่อม/ผู้ดูแล | ใช้ตัวแสดงวันที่ร่วมกัน; แก้ตัวกรอง native date บนแดชบอร์ดผู้บริหาร; API วันที่พนักงานรับกฎเดียวกัน |
| Backend | ลงทะเบียน AddCalendarInput ที่ MVC; ใช้ invariant culture กับข้อมูลสำหรับระบบ; วันปัจจุบันสำหรับงานปฏิทิน/สิทธิ์ลาใช้ HospitalTime.Today |
| ส่งออก | PDF และการแจ้งเตือนแสดง พ.ศ.; Excel รายงานลาบันทึก Gregorian serial และใช้ Buddhist number format |

Excel ใช้ extended LCID ระบุชนิดตัวเลข/ปฏิทิน/ภาษา ตาม [เอกสารรูปแบบตัวเลข](https://help.libreoffice.org/latest/ast/text/shared/01/05020301.html) เพื่อให้ค่าที่เก็บยังนำไปคำนวณวันที่ได้

## การตรวจสอบ

- Backend tests ครอบคลุม JSON parsing, MVC HTTP/model binding ด้วย DTO สร้าง/แก้ไข/preview จริง, query date/year, leap day, วันหยุด/เสาร์อาทิตย์/ครึ่งวัน, ขอบเขตปีงบประมาณ และ XML/serial ของ Excel
- Frontend tests ครอบคลุมการพิมพ์ทั้งสองปี การแสดงข้อมูลเดิมและ payload UTC ของ Fleet
- `npx playwright test --config playwright.dates.config.ts` ทดสอบคอมโพเนนต์จริงใน Edge ภายใต้ภาษาไทย/อังกฤษ และ timezone Bangkok/UTC/Los Angeles รวมถึงเลือกวันจากปฏิทิน ใช้ fixture แยก ไม่เชื่อมฐานข้อมูล
- `npm test`, `npm run build` และ `dotnet test backend/Hop.Api.Tests --no-restore` เป็นชุดตรวจหลัก เครื่องที่ไม่มี .NET 9 ต้องกำหนด `DOTNET_ROLL_FORWARD=Major` ก่อนรัน tests
- ยังไม่ได้ทดสอบ workflow จริงครบทุกหน้าด้วยฐานข้อมูล PRD และไม่ได้เปิดไฟล์ส่งออกใน Microsoft Excel จริง การทดสอบ Excel ตรวจค่ากับรูปแบบในไฟล์

## ข้อมูลเดิมและการนำขึ้นระบบ

ใช้ `deploy/sql/18-calendar-year-audit.sql` ใน DBeaver แบบ Execute SQL Script หาก connection อยู่ในสถานะ aborted ให้รัน `ROLLBACK;` ก่อน สคริปต์สร้างเพียง temporary table และไม่แก้ข้อมูลแอป:

1. แสดงจำนวน/รายการคอลัมน์วันที่และปีผิดช่วงทั่ว schema public
2. ตรวจสถานะล่าสุดของ `01a0b2c5-06d4-75f4-bf0f-f869ba1b5183` รวมทั้งกรณีหาไม่พบ
3. เปรียบเทียบ used/pending กับคำขอ และแสดงจำนวนวันที่คำนวณตามวันทำงาน/วันหยุด
4. แยกรายการที่มีคำขอยกเลิกและข้อมูลผิดเงื่อนไขเพื่อให้ตรวจเพิ่มเติม

**สคริปต์ตรวจสอบยังไม่ได้รันบน PostgreSQL ในเครื่องนี้ เพราะ Docker daemon ไม่พร้อมใช้งาน** ไม่มีการเชื่อมต่อหรือแก้ PRD และไม่ถือว่าสคริปต์ซ่อมก่อนหน้าเคยสำเร็จ ห้ามรันสคริปต์ซ่อมเก่าต่อโดยอัตโนมัติจากผลตรวจนี้

ข้อมูลเดิมที่ยังเก็บปีผิดต้องซ่อมวันที่ จำนวนวัน และยอดที่เกี่ยวข้องร่วมกันอย่างตรวจสอบได้ การแก้โค้ดไม่ย้ายยอดย้อนหลัง และจะปฏิเสธการส่งคำขอเดิมที่ยังมีปีผิดก่อนคำนวณสิทธิ์
