# บันทึกข้อความทั่วไป

## แบบรายงานผลการปฏิบัติงานนอกเวลา

### เอกสารสองชุดและหลักฐานเบิกจ่าย

- ฟอร์มเดียวสร้าง `workReport` (A4 แนวตั้ง ผู้รายงานซ้าย/ผู้ควบคุมขวา) และ `paymentEvidence` (A4 แนวนอน ตารางครบทุกวันในเดือน) ดาวน์โหลด DOCX/PDF แยกแต่ละรายงานจากแท็บ Preview ชื่อและตำแหน่งจากบัญชีจริง ไม่ใช่ลายเซ็นหรือสถานะอนุมัติ
- เลือกเดือนเอกสาร รวมเวลาหลายช่วงในวันเดียวก่อนตัดเศษชั่วโมง แยกงานข้ามคืนที่เที่ยงคืน ช่วงเวลาเป็นแบบเริ่มรวม/สิ้นสุดไม่รวม จึงรับเวลาสิ้นสุด 00:00 ของต้นเดือนถัดไปได้เมื่อไม่มีนาทีทำงานนอกเดือน ตรวจไม่ให้ช่วงเวลาซ้อนกันหรือมีเวลาทำงานนอกเดือน
- ฟอร์มแสดงชั่วโมงทำงานจริงแยกจากชั่วโมงเบิกได้สูงสุดและชั่วโมงที่ยืนยัน ตามกฎที่ผู้ใช้กำหนด: วันปกตินับหลัง 16:30 น. รวมทุกช่วงก่อนตัดเศษ สูงสุด 4 ชม./วัน (18:00–22:00 ได้ 4 ชม.); วันหยุดนับเวลาจริง หักเฉพาะส่วนทับพัก 12:00–13:00 น. แล้วตัดเศษ สูงสุด 7 ชม./วัน (08:30–16:30 ได้ 7 ชม.) ชั่วโมงเบิกเริ่มต้นเป็นเพดาน ปรับลดได้แต่เพิ่มเกินไม่ได้ ทั้ง Frontend และ Backend ตรวจตรงกัน
- `Correspondence:OvertimePayment` กำหนด `WeekdayRate=50`, `HolidayRate=60`, `PayerName=นางสาวรสริน แสนซ้าย` ฟอร์มอ่านอย่างเดียว ผู้รับรองใช้ผู้ควบคุมคนเดียวกับรายงานผล ช่องลายมือชื่อและวันที่รับเงินว่างสำหรับลงจริง
- `Correspondence:OvertimePayment:Rules` กำหนด `WeekdayStart=16:30`, `WeekdayMaxHours=4`, `HolidayMaxHours=7`, `BreakStart=12:00`, `BreakEnd=13:00` ส่งกลับเป็น `rules` ใน payment-options เพื่อให้ฟอร์มใช้ค่าเดียวกับ Backend กฎอิงประเภทวันที่เลือก โดยค่าเริ่มต้นมาจากปฏิทิน HOP
- วันหยุดเริ่มจากเสาร์–อาทิตย์และ `LeaveHolidays` ที่เปิดใช้งาน เปลี่ยนประเภทวันก่อนยืนยันได้ ยอดเงินและตัวอักษรคำนวณใหม่บน Backend เสมอ การแก้ฟอร์มหรือชั่วโมงเบิกยกเลิกการยืนยันและ Preview ทั้งคู่ ต้องยืนยันใหม่ก่อนสร้างไฟล์
- `GET /api/correspondence/overtime-report/payment-options?month=YYYY-MM` คืนอัตรา กฎชั่วโมงเบิก ชื่อผู้จ่ายเงิน และวันที่เป็นวันหยุดในเดือน ใช้ปี ค.ศ. ใน API และแสดง พ.ศ. บนฟอร์ม
- `POST /api/correspondence/overtime-report/render-bundle` รับ `{report: <OvertimeReportRequest เดิม>, payment: {month: "2026-11", days: [{date: "2026-11-06", dayType: "weekday", claimHours: 4}]}}` ตรวจทุกวันที่มีงานและไม่รับวันซ้ำ/วันไม่มีงาน คืน `{workReport: MemoFiles, paymentEvidence: MemoFiles}` เมื่อสร้างทั้งคู่สำเร็จเท่านั้น คง endpoint `render` เดิมสำหรับความเข้ากันได้
- workReport รุ่น `overtime-report-v3` จาก render-bundle แสดงชั่วโมงเบิกที่ยืนยันตรงกับหลักฐาน เช่น วันหยุด 08:30–16:30 แสดง `(7 ชม.)` คงวัน–เวลาและรายละเอียดงานจริง กรณีหลายรายการในวันเดียวหรือข้ามคืน ระบุ `รวมเบิก DD/MM/พ.ศ.: N ชม.` ในรายการแรกที่ครอบคลุมวันนั้นเพียงครั้งเดียว ค่าเวลาจริงในข้อมูลต้นทางไม่ถูกแก้ ส่วน endpoint render เดิมยังใช้รูปแบบและชั่วโมงจริงเดิม
- ทั้งสอง endpoint ใช้สิทธิ์ `Correspondence.Use` และ `Cache-Control: no-store` เนื้อหาและไฟล์อยู่ในหน่วยความจำเท่านั้น ไม่เก็บฐานข้อมูล ดิสก์ Cache หรือ Log ของเอกสาร คืน object URLs ทั้งสี่รายการเมื่อแทนที่/ล้าง/ออกจากหน้า และเตือนก่อนออกจนดาวน์โหลดแต่ละรายงานอย่างน้อยหนึ่งรูปแบบแล้ว
- ปุ่ม “ดูเต็มหน้า” เปิด PDF ของรายงานที่เลือกในแท็บใหม่จาก Blob URL เดียวกับ Preview โดยใช้ `noopener noreferrer` ไม่ส่งไฟล์กลับไปเก็บบนเซิร์ฟเวอร์
- หลักฐานเบิกจ่ายรุ่น `overtime-payment-v2` จัดข้อความจำนวนเงินตัวอักษรและข้อความรับรองกึ่งกลางเหนือส่วนลงชื่อผู้รับรอง โดยคงป้ายรวมจ่ายเงินทางซ้าย ใช้รูปแบบเดียวกันใน PDF และ DOCX

- เลือก “รายงานผลการปฏิบัติงานนอกเวลาราชการและวันหยุดราชการ” จากช่อง **เลือกเทมเพลต** ในหน้า `/correspondence/create` เดิม ไม่มีเมนูหรือ URL แยก ใช้สิทธิ์ `Correspondence.Use` เดิม
- เมื่อเลือกแบบรายงานจะแสดงฟอร์มตารางแทนฟอร์มบันทึกข้อความ จึงไม่ต้องกรอกเลขหนังสือ เรื่อง ผู้รับ หรือส่วน ผอ. ที่ไม่มีในภาพตัวอย่าง หน่วยงานที่เลือกไว้เป็นค่าเริ่มต้นของรายงาน ส่วนผู้ควบคุมเริ่มต้นเป็นหัวหน้าหน่วยงานของบัญชีผู้ใช้งาน หากมีหลายคนให้เลือกเอง (คงหัวหน้าที่เลือกจากฟอร์มเดิมได้เมื่ออยู่หน่วยงานของผู้ใช้) เปลี่ยนกลับเป็นเทมเพลตบันทึกข้อความได้ โดยยืนยันก่อนทิ้งข้อมูลรายงานที่กรอกค้างอยู่
- รายงานใช้ A4 แนวตั้ง ฟอนต์ TH SarabunPSK และตาราง 5 คอลัมน์: วัน/เดือน/ปี ลักษณะงานที่ปฏิบัติ ปริมาณ (หน่วยนับ) เวลา หมายเหตุ พร้อมส่วนลงชื่อผู้รายงานและผู้ควบคุม เลือกผู้ควบคุมจากผู้อนุมัติที่เปิดใช้งานทุกหน่วยงานได้ ชื่อและตำแหน่งดึงจากบัญชีจริง ไม่แสดงภาพลายเซ็นหรือถือว่าอนุมัติในระบบ
- รายชื่อผู้อนุมัติ (`approvers` ใน API options) รวมบทบาท DepartmentHead, หัวหน้าหน่วยงานสูงสุด, Director และบทบาทที่มีสิทธิ์อนุมัติลา/ยกเลิกลา/ตรวจสอบรถ/อนุมัติรถที่เปิดใช้งาน ตรวจบัญชี บทบาท และสิทธิ์ปัจจุบันอีกครั้งเมื่อสร้างไฟล์ การเปลี่ยนหน่วยงานรายงานไม่เขียนทับผู้ควบคุมที่เลือกไว้ ช่องหัวหน้ากลุ่มงานในบันทึกข้อความทั่วไปใช้รายชื่อผู้อนุมัติชุดเดียวกันและเริ่มต้นด้วยหัวหน้าหน่วยงานของผู้ใช้ หากไม่มีหรือมีหลายคนให้เลือกเอง การเปลี่ยนหน่วยงานไม่ล้างผู้ลงนามที่เลือก ส่วน Director ยังคงดึงผู้ดำรงตำแหน่งปัจจุบันอัตโนมัติ
- แต่ละวันเว้นห่างหนึ่งบรรทัด ตารางสูงตามเนื้อหาจริง ไม่ขยายพื้นที่ว่างให้เต็มตารางหรือเพิ่มแถวว่างหลังวันสุดท้าย ทั้ง DOCX และ PDF
- เพิ่มวันทำงานได้ 1–50 รายการ และงานได้ 1–20 งานต่อรายการ (รวมไม่เกิน 500 งาน / 60,000 ตัวอักษร) แต่ละงานมีข้อความปริมาณ/หน่วยนับที่จับคู่กัน วันเดียวกันหลายช่วงและงานข้ามคืนรองรับเมื่อเลือกวันสิ้นสุดจริง ไม่รับรายการช่วงเวลาเดียวกันซ้ำ
- ชั่วโมงในวงเล็บคำนวณจากวัน–เวลาเริ่มถึงสิ้นสุดอัตโนมัติ ตัดเศษชั่วโมงทิ้ง ช่องชั่วโมงปิดแก้ไข เช่น 03:00–07:59 ได้ 4 ชั่วโมง และช่วงที่ไม่ถึงหนึ่งชั่วโมงแสดง 0 ชั่วโมง ไม่หักเวลาพักหรือคำนวณสิทธิ์เบิกจ่ายเพิ่ม รองรับงานข้ามคืนเมื่อระบุวันสิ้นสุดจริง
- ช่องเวลาของรายงานรับนาที 00–59 และตัวเลือกนาทีแสดงครบทีละ 1 นาที Backend คำนวณชั่วโมงใหม่จากช่วงเวลาจริงทุกครั้ง ไม่ใช้ค่า `hours` ที่ส่งมาจากเบราว์เซอร์หรือไคลเอนต์รุ่นเก่า
- ฟอร์มจัดช่วงเริ่มและสิ้นสุดเป็นสองบัตร ช่องวันที่/เวลาขนาดเดียวกัน พร้อมแถบชั่วโมงอัตโนมัติ ป้ายจำนวนงาน และช่องลักษณะงาน/ปริมาณที่สูงเท่ากันในตอนเริ่มกรอก มือถือเรียงลงมาโดยยังคงข้อมูล การคำนวณ และรูปแบบไฟล์เดิม
- `POST /api/correspondence/overtime-report/render` ตรวจข้อมูลและสิทธิ์อีกครั้ง สร้าง DOCX/PDF ชุดเดียวในหน่วยความจำ พร้อม `Cache-Control: no-store` ไม่บันทึกเอกสาร เนื้อหา หรือไฟล์บนเซิร์ฟเวอร์ ข้อผิดพลาดการ render บันทึกเฉพาะชนิดข้อผิดพลาด
- Preview หมดอายุเมื่อแก้ข้อมูล ยกเลิกคำขอที่ยังสร้างอยู่และคืน object URLs เมื่อล้าง เปลี่ยนเทมเพลต หรือออกจากหน้า เช่นเดียวกับบันทึกข้อความเดิม ตารางรองรับการแบ่งหน้าและหัวตารางซ้ำ รายงานนี้สร้างจากภาพอ้างอิง ไม่ใช่การตรวจไฟล์ Word ต้นฉบับ

`/correspondence/create` สำหรับผู้มีสิทธิ์ `Correspondence.Use`; `/correspondence/mine` เปลี่ยนทางมาหน้านี้ภายใต้สิทธิ์เดียวกัน ไม่มีการเก็บประวัติเอกสาร

## กำหนดสิทธิ์

- ติดตั้งข้อมูลสิทธิ์ด้วย `docs/sql/correspondence-access.sql` ผ่าน DBeaver หลังตรวจฐานข้อมูลเป้าหมาย สคริปต์รันซ้ำได้ ไม่เพิ่ม schema และไม่มอบบทบาทแก่ผู้ใช้ทั่วไป
- SuperAdmin เปิดจัดการผู้ใช้ เลือกสร้าง/แก้บัญชี เพิ่มบทบาท “ผู้ใช้งานสารบรรณ” โดยคงบทบาทเดิมไว้ ถอนสิทธิ์ด้วยการเอาบทบาทนี้ออก
- Admin และ SuperAdmin มีสิทธิ์จากบทบาทเดิม ส่วนบทบาทอื่นไม่มีสิทธิ์โดยอัตโนมัติ
- เฉพาะบัญชีที่มีบทบาท SuperAdmin ซึ่งยังเปิดใช้งานในฐานข้อมูลเท่านั้น เปลี่ยนบทบาทที่ให้สิทธิ์สารบรรณหรือแก้การผูกสิทธิ์นี้กับบทบาทอื่นได้
- ผู้ดูแลทั่วไปยังแก้ข้อมูลผู้ใช้โดยคงบทบาทที่ถูกล็อกไว้ได้ การเปลี่ยนบทบาท Admin/SuperAdmin ก็ถูกป้องกันด้วย เพราะเป็นช่องทางให้สิทธิ์สารบรรณ
- Backend ตรวจ permission จากฐานข้อมูลทุกคำขอ เมื่อถอนสิทธิ์ API ครั้งถัดไปได้รับ 403; เมนูปรับตามเมื่อรีเฟรชข้อมูลบัญชีหรือเข้าสู่ระบบใหม่ เอกสารที่ดาวน์โหลดแล้วเรียกคืนไม่ได้
- Audit เดิมบันทึกรหัสบทบาทก่อน–หลัง ไม่บันทึกเนื้อหาบันทึกข้อความ

- `GET /api/correspondence/options` อ่านหน่วยงานและผู้ดำรงบทบาทที่เปิดใช้งาน
- `POST /api/correspondence/render` ตรวจข้อมูลจริงและคืน DOCX/PDF base64 ชุดเดียวกัน พร้อม `Cache-Control: no-store`
- ผู้เสนออ่านจากบัญชีที่ยืนยันตัวตน หัวหน้าใช้บทบาท `DepartmentHead` / `หัวหน้าหน่วยงานสูงสุด` ในหน่วยงานที่เลือก ผู้อำนวยการใช้บทบาท `Director` ที่เปิดใช้งานเพียงหนึ่งบัญชีเท่านั้น Backend ดึงจากฐานข้อมูลตอนสร้างไฟล์ ไม่ใช้ DirectorUserId ที่ส่งจากเบราว์เซอร์ หากไม่มีหรือมีหลายบัญชีจะหยุดให้ผู้ดูแลตรวจสอบ ช่องชื่อ ผอ. ในฟอร์มเป็นแบบอ่านอย่างเดียว
- ฟอร์มรับเฉพาะย่อหน้าและ text runs ที่อนุญาต ไม่รับ HTML ภาพ ตาราง หรือ URL สำหรับแทรกไฟล์
- เอกสารสร้างในหน่วยความจำ ไม่มีการบันทึกเอกสาร เนื้อหา หรือประวัติลง DB/ดิสก์/log; ข้อผิดพลาด renderer บันทึกเฉพาะชนิด exception
- Browser เก็บฟอร์มและ blob ในหน่วยความจำ แก้ไขแล้ว Preview หมดอายุ ล้าง/ออกจากหน้าจะคืน blob URLs ไม่มี document localStorage
- Template `assets/correspondence/memo-v1.docx` แปลงจากสำเนาไฟล์ .doc ของผู้ใช้และแทนข้อมูลบุคคลด้วย placeholders โดยไม่แก้ไฟล์บนแชร์
- PDF ใช้ QuestPDF และ TH SarabunPSK ที่ติดตั้งในชุดแอป Preview ใช้ PDF.js ภายในเว็บ ไม่พึ่ง PDF plugin บนมือถือ
- แก้ข้อความมาตรฐานได้จาก `Correspondence:Closings`, `Correspondence:HeadComments`, `Correspondence:DirectorComments` ใน Configuration ไม่มีการเพิ่มสิทธิ์หรือ migration

ทดสอบตัวอย่างชื่อสมมุติทั้งหน้าเดียว/สามหน้า: เปิด DOCX ด้วย Microsoft Word และ render ทุกหน้า เทียบกับ QuestPDF; ทดสอบ renderer บน Windows และ Linux .NET 9 container แล้ว ผลตัดหน้าของ Word กับ PDF อาจแตกต่างกัน

ไม่ต้องติดตั้ง Word หรือ LibreOffice บนเซิร์ฟเวอร์; Word ใช้ตรวจไฟล์บนเครื่องพัฒนาเท่านั้น

## เทมเพลตเนื้อหา

- ข้อมูลชื่อ ตำแหน่ง และหน่วยงานใช้ค่าจากฟอร์มด้านบนโดยตรง ไม่แสดงช่องซ้ำในส่วนเทมเพลต
- วัน–เวลาปฏิบัติงานเพิ่มได้ 50 รายการ แต่ละรายการมีวันเริ่ม เวลาเริ่ม วันสิ้นสุด เวลาสิ้นสุด ใช้เวลาไทยแบบ 24 ชั่วโมงและวันที่ พ.ศ. วันสิ้นสุดตามวันเริ่มจนกว่าจะถูกแก้เอง ไม่เดาว่าข้ามวันจากเวลา
- `{work_periods}` เป็นรายการวัน–เวลาที่จับคู่และเรียงตามเวลาเริ่ม รองรับข้ามวัน/เดือน/ปี; `{work_dates}` และ `{work_times}` เดิมยังใช้ได้และมีเลขลำดับตรงกัน รายการที่เริ่มกรอกต้องครบ เวลาสิ้นสุดต้องหลังเริ่ม และห้ามซ้ำทั้งช่วง รายการว่างที่ยังไม่ได้กรอกจะถูกข้าม หากว่างทั้งหมดคง placeholder ไว้

- มี 4 แบบใน `Correspondence:ContentTemplates` ของ Configuration: `MEMO_WORK_CERT`, `MEMO_OT_REQUEST`, `MEMO_OT_CLAIM`, `MEMO_PURCHASE_IT` แยกจากไฟล์ Word ที่กำหนดหน้ากระดาษและส่วนลงนาม
- แต่ละแบบมี `Code`, `Name`, `SubjectTemplate`, `BodyTemplate` (หนึ่งข้อความต่อย่อหน้า), `ClosingTemplate`, `Variables`, `IsActive`; เปลี่ยนข้อความใน Configuration และเริ่ม Backend ใหม่ได้โดยไม่แก้ Source Code ไม่เพิ่มฐานข้อมูลหรือหน้าจัดการในเฟสนี้
- รองรับ `{full_name}`, `{position}`, `{department}` จาก HOP และช่องกรอกเดือน/ปี พ.ศ. วันเวลา รายละเอียดงาน เหตุผล จำนวนรายการ และจำนวนเงิน ตัวเลขเงินไม่เกิน 12 หลักและทศนิยม 2 หลัก แปลง `{amount_text}` อัตโนมัติ
- การเลือกแบบหรือแก้ตัวแปรยังไม่แทนข้อความเดิม จนกด “เติมข้อความจากเทมเพลต”; หากมีเนื้อหาอยู่ให้ยืนยันก่อนแทนที่ เรื่อง/เนื้อหา/ลงท้ายแก้ต่อได้ และ Preview เดิมหมดอายุ
- ช่องว่างคง `{variable}` ให้แก้เอง ทั้ง Frontend และ Backend ห้ามสร้างไฟล์ที่ยังมี placeholder รูปแบบนี้อยู่ รวมกรณีแยกเป็นหลาย text runs
- ข้อความเป็นร่างตัวอย่าง ไม่ได้ยืนยันการปฏิบัติงานหรือแนบเอกสารจริง ผู้ใช้งานต้องตรวจถ้อยคำและเอกสารประกอบก่อนนำไปใช้
- ไม่มีการบันทึกค่าตัวแปรหรือข้อความลง LocalStorage/ฐานข้อมูล ส่วนการมอบสิทธิ์สารบรรณยังเป็นกฎ SuperAdmin เดิม

### รูปแบบร่วมทุกเทมเพลต

- ช่องเรื่องที่ยาวหลายบรรทัดมีเส้นใต้เต็มความกว้างของช่องแยกทุกบรรทัด ทั้ง Word และ PDF โดยวางคำว่า “เรื่อง” ที่บรรทัดแรก
- ย่อหน้าเนื้อหาตั้งต้นใช้เต็มบรรทัดภาษาไทย Word ใช้ `thaiDistribute`; PDF วัดและตัดบรรทัดด้วยฟอนต์และ shaping engine ที่ใช้พิมพ์จริง แล้วกระจายระยะตัวอักษรแทนการขยายเฉพาะช่องว่างระหว่างคำ ไม่แยกสระและวรรณยุกต์ บรรทัดสุดท้ายไม่ถูกยืด รายการลำดับและการจัดแนวที่ผู้ใช้เลือกเองยังคงรูปแบบเดิม
- ความเห็นหัวหน้าตั้งต้นเป็น `- เห็นสมควรอนุมัติ` และรองรับข้อความเดิม `เห็นสมควรอนุมัติ` โดยเติมขีดนำหน้าเมื่อสร้างไฟล์ ความเห็น ผอ. เช่น “อนุมัติ” ใช้ตัวหนาใน Word และ PDF โดยไม่ทำให้เอกสารมีสถานะอนุมัติในระบบ
- เมื่อกดสร้าง Preview จะตรวจข้อมูลจำเป็นก่อนเรียก API แสดงข้อผิดพลาดและเลื่อน/โฟกัสช่องแรกที่ต้องแก้ รวมวันเอกสาร ผู้ลงนาม และตัวแปรในเทมเพลต หากตัวแปรกรอกแล้วแต่เนื้อหายังเป็น placeholder จะพาไปปุ่มเติมข้อความจากเทมเพลตเพื่อให้ผู้ใช้ยืนยันการแทนข้อความตามเดิม

### เทมเพลตเบิกค่าตอบแทนนอกเวลา

- ใช้ข้อความสองย่อหน้าตามตัวอย่าง: อ้างอิงการอนุมัติปฏิบัติงานเดิม แล้วขอเบิกค่าตอบแทนเมื่อปฏิบัติงานเสร็จ พร้อมข้อความคืนเงินหากพบการเบิกจ่ายผิดพลาด ลงท้าย “จึงเรียนมาเพื่อโปรดทราบและพิจารณาอนุมัติ”
- ส่วน “เลขหนังสือและวันที่อ้างอิง” แยกกรอกเลขที่หน่วยงานและเลขทะเบียนส่งเป็นตัวเลข แล้วประกอบ `{reference_document_number}` เช่น `นน 0033.307/92` พร้อมแสดงช่องอ่านอย่างเดียวพื้นเขียวอ่อน และเลือก `{reference_document_date}` แยกจากเลขที่/วันที่ของหนังสือฉบับที่กำลังสร้าง ไม่มีรายการเอกสารเก่าให้เลือกจากฐานข้อมูลในเฟสนี้
- เลือก `{period_start}` / `{period_end}` และกรอก `{work_detail}` สำหรับช่วงและงานที่ได้รับอนุมัติ วันที่เติมในเนื้อหาเป็นชื่อเดือนภาษาไทย ปี พ.ศ.; ไม่รับช่วงวันสิ้นสุดก่อนวันเริ่ม ข้อมูลที่ยังไม่กรอกคง placeholder และต้องเติมก่อนสร้างไฟล์ตามเดิม
- ช่วงวันเริ่ม–สิ้นสุดตั้งต้นเป็นวันที่ 1 ถึงวันสุดท้ายของเดือน/ปี พ.ศ. ที่เลือก และคำนวณใหม่เมื่อเปลี่ยนเดือนหรือปี รวมกุมภาพันธ์ 28/29 วัน ผู้ใช้ยังแก้วันที่เองได้จนกว่าจะเลือกเดือนหรือปีใหม่ ไม่เปลี่ยนวันที่หนังสืออ้างอิงหรือเนื้อหาที่เติมไปแล้วอัตโนมัติ ปีที่ยังกรอกไม่ครบจะล้างช่วงวันเดิมและไม่ให้เติมข้อความจนกว่าปีถูกต้อง

### เทมเพลตรับรองการขึ้นปฏิบัติงาน

- ย่อหน้าแรกแสดงคำนำหน้า ชื่อ ตำแหน่ง และกลุ่มงาน พร้อมรายละเอียดงานก่อนรายการวัน–เวลา ไม่แยกย่อหน้า “โดยปฏิบัติงาน” อีก
- ย่อหน้ารับรองแสดงคำนำหน้า ชื่อ และตำแหน่งอีกครั้งหลัง “ในการนี้ ข้าพเจ้า” โดยยังใช้ข้อมูลผู้เสนอจาก HOP เดิม
- รายการวัน–เวลาใช้เลขลำดับแบบ `1.` และ `2.` รวมตัวแปรวันและเวลาแบบเดิม โดยยังเรียงตามเวลาเริ่มและจับคู่วัน–เวลาไว้ด้วยกัน
- เมื่อเติม `{work_periods}` จะแยกแต่ละรายการเป็นย่อหน้าเยื้องระดับ 1 ให้เลขลำดับทุกรายการเริ่มตรงกับย่อหน้าเนื้อหา ทั้ง DOCX และ PDF ไม่เติมเลขลำดับซ้ำ
- `{name_prefix}` อ่านคำนำหน้าที่รองรับจากชื่อในบัญชีเป็นค่าเริ่มต้น โดยแยกออกจาก `{full_name}` เพื่อไม่เติมซ้ำ หากชื่อไม่มีคำนำหน้าให้เลือกในส่วนเทมเพลตก่อนสร้างไฟล์ การเลือกมีผลต่อข้อความที่เติมเท่านั้น ไม่เปลี่ยนชื่อใน Profile หรือชื่อส่วนลงนามที่ดึงจากบัญชีตามเดิม

### เทมเพลตขออนุมัติปฏิบัติงานนอกเวลา

- หัวเอกสารทุกเทมเพลตจัดป้าย “วันที่” ชิดขวาของช่องป้าย เพื่อให้ชิดกับค่าวันที่และมีช่องว่างนำหน้าป้าย ทั้ง DOCX และ PDF

- เพิ่มแบบที่ 4 `MEMO_OT_REQUEST` สำหรับขออนุมัติปฏิบัติงานนอกเวลาราชการและวันหยุดราชการ แยกจาก `MEMO_OT_CLAIM` ซึ่งใช้ขอเบิกเงิน ใช้ข้อความเหตุผล ภาระงาน และหลักเกณฑ์ 7.1/7.2 ตามภาพตัวอย่างที่ผู้ใช้ให้
- ชื่อกลุ่มงานในสองย่อหน้าแรกใช้หน่วยงานที่เลือกด้านบน รายชื่อ `{staff_list}` ดึงบุคลากรที่เปิดใช้งานทุกหน่วยงานผ่าน `GET /api/correspondence/departments/{departmentId}/people?includeOtherDepartments=true` ภายใต้สิทธิ์สารบรรณเดิม ตัดบัญชีที่มีบทบาท Admin หรือ SuperAdmin ออกแม้มีบทบาทอื่นร่วมด้วย ส่งเฉพาะรหัส ชื่อ ตำแหน่ง และรหัสหน่วยงาน ไม่ส่งข้อมูลติดต่อหรือ credentials เมื่อไม่ระบุ query จะยังส่งเฉพาะคนในหน่วยงานตามเดิม
- เลือกเฉพาะคนในหน่วยงานเป็นค่าเริ่มต้น เพิ่มบุคลากรข้ามหน่วยงานหรือเอาผู้ไม่เกี่ยวข้องออกก่อนเติมข้อความได้ (สูงสุด 50 คน) เปลี่ยนหน่วยงานแล้วโหลดรายชื่อใหม่และยกเลิกคำขอเก่า ไม่ใช้รายชื่อกลุ่มงานก่อนหน้า หากโหลดไม่สำเร็จ ไม่พบผู้ที่เลือก หรือผู้ที่เลือกไม่มีตำแหน่ง จะยังเติมข้อความไม่ได้ จนกว่าจะลองใหม่ แก้ Profile หรือเอารายนั้นออก เมื่อเติมข้อความจะแปลงเป็นย่อหน้ารายการลำดับแยกคน ไม่ใช้ตารางและไม่สร้างข้อมูลผู้ใช้เพิ่ม
- `{supervisor_name}` เติมชื่อผู้อนุมัติที่เลือกในส่วนลงนามอัตโนมัติ และยังพิมพ์แก้ไขหรือล้างชื่อได้ หากมีหัวหน้าหลายคนจะรอเลือก ไม่เดาชื่อ เมื่อผู้ใช้แก้ชื่อเองจะไม่เขียนทับจากการเปลี่ยนหัวหน้าหรือเดือน แต่เมื่อเปลี่ยนกลุ่มงานจะล้างการพิมพ์ทับและใช้ผู้ลงนามที่เลือกอยู่ การเปลี่ยนช่องนี้ยังไม่แทนที่เนื้อหาจนกดเติมข้อความจากเทมเพลต
- เลือกเดือนและปี พ.ศ. เพื่อเติมช่วงวันที่ 1–สิ้นเดือนตามกลไกเดิม ข้อมูลไม่ครบยังคง placeholder และสร้างไฟล์ไม่ได้จนกว่าจะเติมครบ แก้เนื้อหาหลังเติมได้ตามเดิม ไม่มีการส่งอนุมัติหรือจ่ายเงินจากการสร้างเอกสารนี้
# ชื่อบุคคลจากบัญชี HOP

API ข้อมูลประกอบสารบรรณและรายชื่อบุคลากรส่ง `namePrefix` กับ `fullname` แยกกัน และส่ง `name` เป็นคำนำหน้าต่อด้วยชื่อเต็มจากฐานข้อมูล โดยตัดช่องว่างหัวท้าย หากไม่มีคำนำหน้าใช้ชื่อเดิม ไม่เดาคำนำหน้าจากชื่อหรือเพศ

ผู้เสนอ หัวหน้า ผู้อำนวยการ ผู้ควบคุม บุคลากรที่เลือก รวมถึงผู้รายงาน ผู้รับเงิน และผู้รับรองในรายงานทั้งสอง ใช้ชื่อจากแหล่งเดียวกัน ส่วนชื่อผู้จ่ายเงินยังใช้ Configuration เดิม เทมเพลตที่ใช้ `{name_prefix}{full_name}` จะเติมจากสองฟิลด์จริง ส่วน `{full_name}` เพียงตัวเดียวใช้ชื่อประกอบแล้ว ไม่มีช่องเลือกคำนำหน้าซ้ำในเทมเพลต ให้แก้ที่ Profile

ชื่อผู้ลงนามตรวจจากบัญชีจริงเมื่อสร้างเอกสาร ส่วนข้อความที่ผู้ใช้พิมพ์เองหรือเติมไว้แล้วไม่ถูกเขียนทับอัตโนมัติ ไม่มีการแก้ข้อมูลชื่อเดิมหรือเพิ่ม migration ในการเชื่อมการแสดงชื่อนี้

## การตัดคำไทย

PDF บันทึกข้อความใช้ ICU4N `60.1.0-alpha.440` และ ICU4N.Resources รุ่นเดียวกันที่ติดตั้งมากับ Backend เพื่อหาจุดตัดคำไทย แล้ววัดความกว้างด้วยฟอนต์และรูปแบบตัวอักษรจริงของ QuestPDF ใช้กับช่องเรื่องและเนื้อหาทุกการจัดแนว โดยคำที่คร่อมหลายช่วงตัวหนา/เอียง/ขีดเส้นใต้ยังแบ่งคำร่วมกัน ไม่แทรกอักขระซ่อนหรือเปลี่ยนเนื้อหาที่ผู้ใช้กรอก

หากข้อความต่อเนื่องยาวเกินหนึ่งบรรทัดจึงตัดตามกลุ่มตัวอักษร Unicode ที่ปลอดภัย รวมการไม่แยกสระหน้าไทยออกจากพยัญชนะ การขึ้นบรรทัดและบรรทัดว่างที่ผู้ใช้กำหนดไว้ยังคงอยู่ พจนานุกรมอาจแบ่งคำประสมเป็นคำย่อยที่สมบูรณ์ เช่น “หลัก” กับ “เกณฑ์”

DOCX ส่วนเนื้อหายังให้ Word จัดบรรทัดโดยตั้งภาษา `th-TH` ส่วนช่องเรื่องยังแบ่งตาม PDF เพื่อรักษาเส้นใต้เต็มทุกบรรทัดตามที่ยืนยัน โปรเจกต์ตั้ง `SatelliteResourceLanguages` เป็น `th;en` เพื่อส่งมอบเฉพาะทรัพยากรภาษาไทยและอังกฤษ โดยคง `ICU4N.dll`, `ICU4N.resources.dll` ส่วนกลาง, `th/ICU4N.resources.dll` และ `en/ICU4N.resources.dll` ตามตำแหน่งเดิม ต้องส่งมอบชุด clean publish ทั้งหมด ห้ามคัดลอกเพียง Hop.Api.dll หรือย้ายไฟล์ภาษาไปรวมโฟลเดอร์เอง และไม่มีการเรียกบริการแบ่งคำภายนอกขณะสร้างเอกสาร

## ชื่อไฟล์ดาวน์โหลด

Backend ส่งชื่อฐานใน `fileName` เดิม แล้วเบราว์เซอร์เติม `.pdf` หรือ `.docx` จาก Preview ที่สร้างสำเร็จแล้ว:

- `บันทึกข้อความ-ขอปฏิบัติงานนอกเวลา-เดือนตุลาคม-2569-28.1-นายกฤษฎา แสงวันเพ็ญ.pdf`
- `รายงานผลการปฏิบัติงานนอกเวลา-เดือนตุลาคม-2569-นายกฤษฎา แสงวันเพ็ญ.pdf`
- `หลักฐานการเบิกจ่าย-เดือนตุลาคม-2569-นายกฤษฎา แสงวันเพ็ญ.pdf`

เทมเพลตมี `FileNameTitle` ใน Configuration และ API options ส่งเป็น `fileNameTitle` คำขอสร้างบันทึกข้อความรับ `contentTemplateCode` และ `workMonth` (`YYYY-MM` ค.ศ.) แบบ optional โดยเก็บพร้อมเนื้อหาตอนกดเติมเทมเพลต ไม่เปลี่ยนตามตัวเลือกที่ยังไม่ได้เติม Backend ตรวจเทมเพลตที่เปิดใช้งาน เดือนที่ถูกต้อง และใช้ชื่อผู้เสนอจริงจากบัญชี ไม่รับชื่อไฟล์สำเร็จรูปจาก client

หากไม่มีเดือนงานใช้วันที่ออกหนังสือ หากไม่ได้เลือกเทมเพลตใช้ชื่อเรื่องเป็นชื่อเอกสาร Client เดิมที่ไม่ส่งฟิลด์ใหม่ยังทำงานได้ รายงาน bundle ใช้เดือนเอกสารที่เลือก ส่วน endpoint รายงานเดิมใช้เดือนของรายการวันที่แรก โดยรายงานทั้งสองไม่ใส่เลขทะเบียนส่ง

เลขทะเบียนส่งดึงเฉพาะส่วนหลัง `/` และเก็บจุด เช่น `28.1` ตามเดิม แทนอักขระต้องห้ามและอักขระควบคุมในชื่อไฟล์ด้วยขีด จำกัดชื่อฐานไม่เกิน 235 ไบต์ UTF-8 เพื่อให้นามสกุล `.docx` รวมแล้วไม่เกิน 240 ไบต์ โดยย่อส่วนชื่อเอกสารก่อนแล้วจึงชื่อบุคคลตามกลุ่มตัวอักษรที่ปลอดภัย คงประเภท เดือน ปี และเลขทะเบียนส่งไว้ ไม่มีการเก็บเอกสารหรือข้อมูลชื่อไฟล์ลงฐานข้อมูล
